# Hero video pipeline (self-service tool)

The hero film is generated by a tool the user can run themselves — **do not
hand-edit shots.txt or re-derive the recipe**. The user is non-technical.

## How the user runs it (tell them this if they ask)
1. Put source videos (mp4, landscape, ideally 1080p) in `assets/videos/source/`
2. Edit `hero-timeline.txt` (project root) — one line per moment: `<file> <M:SS>`,
   plus optional `audio: <file>` for the sound under the film
3. Double-click `Make Hero Video.command` (first time: right-click → Open)

## What the tool does (scripts/hero/)
`make-hero.sh` orchestrates:
- `plan-shots.py` — hero-timeline.txt → shots.txt. Encodes the approved recipe:
  rotate across sources (no adjacent repeats until one source remains), pacing
  arc 4.5s holds → 3.2s mid → 5.0s finish, speed 0.64 → 0.96, transitions
  cycle a curated cinematic list (slices/radial/wind/opens). First shot fade,
  last shot zoomin. NEVER use `circlecrop`/`rectcrop` (blackout mid-transition).
- `build-cut.sh` — shots.txt → silent 1920x1080 master (`_work/master.mp4`),
  single ffmpeg pass, Ken Burns push per shot, xfade durations 1.0 → 0.7s.
- `grade.sh natural` — the site ships the NATURAL grade (user's explicit pick;
  "brass is too much"). White-balance fix + grain + vignette baked in.
- Deploys to `assets/videos/hero-loop.mp4` + `hero-poster.jpg` (paths the
  hero markup already references).
- `audio.sh <file>` — masters the ambience loop (`assets/audio/hero-ambience.m4a`,
  -16 LUFS, edge fades) from the video named on the timeline's `audio:` line.

## Site integration gotchas
- `.hero__stage` is `position: fixed` (home.css) — the film is a persistent
  backdrop the whole home page scrolls over.
- `css/media-motion.css` has a blanket rule `main > section.section > * {
  position: relative }` that MUST `:not()`-exclude `.hero__stage`; any fixed
  overlay (like `.sound-toggle`) must live as a direct child of `<main>`,
  outside sections.
- Ambient audio is ON BY DEFAULT as far as browsers allow (user's explicit
  wish): `js/heroAudio.js` tries autoplay, else starts on the visitor's first
  tap/click/keypress anywhere; the `.sound-toggle` pill (speaker icon +
  equalizer bars while playing) mutes. The choice PERSISTS across visits in
  localStorage (`olamide-hero-sound` = "on" | "muted"). Volume/rate constants
  live at the top of `js/heroAudio.js` (user tunes these themselves). True
  unprompted autoplay is impossible (browser policy) — do not promise it.
